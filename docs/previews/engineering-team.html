Configure your engineering team

Six teammates. Separate providers, models, effort, and instructions. Changes stay in this preview.

Engineering team

A tech lead, engineer, reviewer and three QA specialists share a live team room. Build runs follow explicit handoffs, with up to two automatic repair rounds for high or critical findings. Ask and Plan use the normal single-agent workflow.

Each role makes separate model calls using your local CLI login. Blank models use the provider default. The Engineer settings below control implementation. Review and QA assess the diff and recorded checks; browser and visual testing are not automated. High and critical findings block readiness.

Tech lead

Propose an actionable approach, identify risks and acceptance criteria, and hand the work to the engineer. Reconcile feedback from the team.

Engineer

Implement the agreed approach, address team findings, and report changes and verification evidence.

Reviewer

Inspect architecture, correctness, security, and maintainability. Challenge unsupported assumptions and cite specific files and lines.

Functional QA

Assess the request and acceptance criteria against the changes. Look for missing behavior and edge cases.

Regression QA

Assess compatibility, integrations, regression risks, test coverage, and the recorded validation results.

UX QA

Assess user flows, accessibility, loading and error states, and responsive behavior from the supplied code. Clearly identify browser and visual checks that have not been performed. For changes without UI, say this role is not applicable.
